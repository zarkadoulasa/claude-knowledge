# Simon Pittman - Set Up Claude Cowork

> **Creator:** [[Simon Pittman]] · **Channel:** Systems Made Better · **Published:** 2026-04-10 · **Length:** 47:53 · [Watch on YouTube](https://www.youtube.com/watch?v=pl90LATQlHI)

## TL;DR

A beginner walkthrough of [[Claude Cowork]] on a Mac in seven steps, almost all shown live on his own account. (1) Install the desktop app, give Cowork one workspace folder, pick a model. (2) Have Claude draft CLAUDE.md-style global instructions and paste them into Settings › Cowork. (3) Build an About Me folder: `about-me.md`, a `writing-rules.md` distilled from Wikipedia's catalogue of AI-writing tells, and a `memory.md` Claude appends to, all required reading each session. (4) Connect Claude in Chrome, Gmail, Calendar and Notion, teach a drafts-only email habit, and add a "context map" so Claude finds Notion databases first time. (5) Use built-in file skills and add `outputs/` + `projects/` folders. (6) Install and customise Anthropic's plugins. (7) Schedule a weekly briefing and a weekday inbox triage. An addendum covers Dispatch (phone to desktop) and computer-use permissions. The recurring move is letting Claude write its own setup while you review. Some details are dated, notably his claim that scheduled tasks need the computer on, and he never mentions Cowork's native memory or projects (see Caveats).

## Key takeaways

- **One folder scopes what Claude can touch.** Treat it as the shared workspace and keep private material outside [04:15](https://www.youtube.com/watch?v=pl90LATQlHI&t=255s), [04:17](https://www.youtube.com/watch?v=pl90LATQlHI&t=257s). He then breaks the rule for a Desktop demo [05:19](https://www.youtube.com/watch?v=pl90LATQlHI&t=319s). See [[Permissions and Approval Gates]].
- **Global instructions are the most important, most-missed step.** They're rules read at the start of every conversation, in effect a CLAUDE.md [08:14](https://www.youtube.com/watch?v=pl90LATQlHI&t=494s), [09:01](https://www.youtube.com/watch?v=pl90LATQlHI&t=541s). He recommends a Cowork-only set over the account-wide one [08:41](https://www.youtube.com/watch?v=pl90LATQlHI&t=521s). See [[CLAUDE.md as a Router]].
- **Let Claude draft its own configuration.** Dictate role, technical level, tone and safety rules, let Claude write the file, discuss where it lives, paste it into settings [09:16](https://www.youtube.com/watch?v=pl90LATQlHI&t=556s), [11:24](https://www.youtube.com/watch?v=pl90LATQlHI&t=684s). He repeats this for every later step. See [[Set Up Claude Cowork]].
- **End build prompts with "ask me any questions."** Claude then asks structured questions before building [15:24](https://www.youtube.com/watch?v=pl90LATQlHI&t=924s), [15:54](https://www.youtube.com/watch?v=pl90LATQlHI&t=954s). When making skills with skill-creator, ask it to build in AskUserQuestion [33:30](https://www.youtube.com/watch?v=pl90LATQlHI&t=2010s). See [[Build a Skill from a Successful Run]].
- **Three context files do the personalising.** Who you are, how to write without sounding like AI, and an append-or-update memory log, all named as required reading [12:56](https://www.youtube.com/watch?v=pl90LATQlHI&t=776s), [18:45](https://www.youtube.com/watch?v=pl90LATQlHI&t=1125s). See [[Write Anti-AI Writing Rules]] and [[Agent Memory Patterns]].
- **Verify it loaded.** In a fresh task, ask Claude how it's meant to work with you; the reply should cite the files [19:35](https://www.youtube.com/watch?v=pl90LATQlHI&t=1175s), [19:50](https://www.youtube.com/watch?v=pl90LATQlHI&t=1190s). Specific files give specific results [19:29](https://www.youtube.com/watch?v=pl90LATQlHI&t=1169s).
- **Persist corrections.** State the new rule and ask Claude to update memory or instructions so it sticks. His example is always saving email replies as Gmail drafts [26:18](https://www.youtube.com/watch?v=pl90LATQlHI&t=1578s), [26:38](https://www.youtube.com/watch?v=pl90LATQlHI&t=1598s).
- **A context map makes a connected tool findable.** Claude needed several tries to find a Notion page [28:53](https://www.youtube.com/watch?v=pl90LATQlHI&t=1733s). After he dropped `my-context-map.md` into About Me, the same chat hit the right database immediately [30:33](https://www.youtube.com/watch?v=pl90LATQlHI&t=1833s). He says this works for any store and saves tokens [30:44](https://www.youtube.com/watch?v=pl90LATQlHI&t=1844s), [31:03](https://www.youtube.com/watch?v=pl90LATQlHI&t=1863s). See [[Build a Context Map for a Connected Tool]].
- **Separate outputs from working context.** `outputs/<project>/` for deliverables; `projects/<project>/` for that project's CLAUDE.md and memory; Claude asks when unsure whether something is new [35:02](https://www.youtube.com/watch?v=pl90LATQlHI&t=2102s), [35:22](https://www.youtube.com/watch?v=pl90LATQlHI&t=2122s).
- **Skills are tools; plugins are specialists.** A plugin is closer to taking on an expert who arrives with their own kit and methods, and it can be customised to your business [40:37](https://www.youtube.com/watch?v=pl90LATQlHI&t=2437s), [39:44](https://www.youtube.com/watch?v=pl90LATQlHI&t=2384s). See [[Agent Skills]] and [[Build vs Install Third-Party Skills]].
- **Scheduled tasks need sources, a style guide and an output location** [42:18](https://www.youtube.com/watch?v=pl90LATQlHI&t=2538s), [42:57](https://www.youtube.com/watch?v=pl90LATQlHI&t=2577s). His "computer must be on" claim [41:47](https://www.youtube.com/watch?v=pl90LATQlHI&t=2507s) is now dated (see Caveats). See [[Schedule Recurring Claude Tasks]].
- **Model choice is a cost dial.** Extended thinking on. Sonnet for most work, Opus for ambitious work at higher token cost [04:35](https://www.youtube.com/watch?v=pl90LATQlHI&t=275s), [04:55](https://www.youtube.com/watch?v=pl90LATQlHI&t=295s). His desktop clean-up ran on Opus [06:48](https://www.youtube.com/watch?v=pl90LATQlHI&t=408s); he picks Sonnet for a Word doc and Opus to restructure folders [33:14](https://www.youtube.com/watch?v=pl90LATQlHI&t=1994s), [35:36](https://www.youtube.com/watch?v=pl90LATQlHI&t=2136s). See [[Route Tasks to the Right Claude Model]].

### [12:18](https://www.youtube.com/watch?v=pl90LATQlHI&t=738s) Create an 'About Me' folder

**One prompt builds all three** (paraphrased)

## Caveats & disagreements

**Dated or imprecise versus Anthropic docs (checked 2026-09-15)**
- **Scheduled tasks.** He says the computer must be on [41:47](https://www.youtube.com/watch?v=pl90LATQlHI&t=2507s). The Help Center now says Cowork scheduled tasks run remotely even with the computer asleep or the app closed, using connectors and account files. They can't be tied to a local folder, and tasks needing local files or apps run only locally. His always-on-desktop advice now fits local-file tasks, Dispatch and computer use.
- **Free account** [02:41](https://www.youtube.com/watch?v=pl90LATQlHI&t=161s): a Claude account is free, but Cowork itself requires a paid plan.
- **"Wrapper around the Claude Code base model"** [03:42](https://www.youtube.com/watch?v=pl90LATQlHI&t=222s): Anthropic says it shares Claude Code's agentic architecture; it isn't a model.
- **Built-in memory and projects go unmentioned.** Chat memory carries into Cowork only in cloud sessions. Local sessions like his don't use it, so a hand-kept `memory.md` still fills a gap there. Cowork projects now have their own instructions and project-scoped memory; the docs don't say whether that applies to projects made from a local folder. If you use them, his `projects/` folders can duplicate them and leave two memory stores that disagree.
- **Unversioned models.** "Sonnet" and "Opus" only [04:36](https://www.youtube.com/watch?v=pl90LATQlHI&t=276s). See [[Choosing a Claude Model]] for current ones.
- **One Gmail account** [24:15](https://www.youtube.com/watch?v=pl90LATQlHI&t=1455s): third-party guides still report it, but it isn't confirmed in Anthropic docs and may change.
- **"Cowork creates drafts only"** [26:49](https://www.youtube.com/watch?v=pl90LATQlHI&t=1609s) comes from his instruction plus memory, not a product guarantee. Gmail's send, reply and forward tools do now ask for approval before each by default, though Team and Enterprise owners can let members skip that (Beyond the source). Enforce it with connector tool permissions.
- **Privacy toggle** [27:06](https://www.youtube.com/watch?v=pl90LATQlHI&t=1626s): it controls whether new sessions are used for training, and with that the retention period. It doesn't stop data reaching Anthropic (Beyond the source).

**Safety he models poorly**
- He grants Desktop access right after teaching one-folder scoping [05:19](https://www.youtube.com/watch?v=pl90LATQlHI&t=319s). He floats connecting PayPal [23:49](https://www.youtube.com/watch?v=pl90LATQlHI&t=1429s).
- He shows the Chrome setting that acts without asking on unapproved sites. He flags only that you must be comfortable with that, and doesn't advise leaving it off [44:33](https://www.youtube.com/watch?v=pl90LATQlHI&t=2673s), [44:39](https://www.youtube.com/watch?v=pl90LATQlHI&t=2679s).
- He bulk re-dates 41 live tasks with no visible review [31:24](https://www.youtube.com/watch?v=pl90LATQlHI&t=1884s). His safety rule covers delete, send and publish, not edits.

**Evidence quality**
- The demos run on a primed account: connectors already knew him [16:09](https://www.youtube.com/watch?v=pl90LATQlHI&t=969s), the context map was pre-made [29:40](https://www.youtube.com/watch?v=pl90LATQlHI&t=1780s), and the before/after is one query. Output multipliers [02:59](https://www.youtube.com/watch?v=pl90LATQlHI&t=179s) and time savings [46:02](https://www.youtube.com/watch?v=pl90LATQlHI&t=2762s) are unmeasured.
- **Promotions:** the video pitches the creator's paid templates, plugin and framework, and the description carries affiliate links; none are covered here.

**Conflicts with existing vault notes**
- **[[CLAUDE.md as a Router]] / [[Keep CLAUDE.md Lean]].** The vault favours a small router pointing to files read on demand, and warns that bloat lowers adherence. - **[[Claude Code Auto Memory]].** The vault covers Claude Code's automatic memory stored outside the repo. Routines and Scheduled Tasks separates the three: Claude Code desktop tasks need the machine awake, Cowork scheduled tasks now run remotely unless they need local files, and cloud routines need no machine. Keep them distinct.
- **[[Always-On Brain OS]].** Vault "always-on" means autonomous, self-syncing ingestion. His "always-on Mac" [44:18](https://www.youtube.com/watch?v=pl90LATQlHI&t=2658s) means an awake machine for tasks and Dispatch.
- **[[Build a Level 1 Second Brain]].** The vault layout is `context/` + `decisions.md` + `projects/priorities.md`. Simon's adds a writing-style file, merges decisions, preferences and status into `memory.md`, adds a context map, and splits `outputs/` from `projects/<name>/` [35:46](https://www.youtube.com/watch?v=pl90LATQlHI&t=2146s). That's another data point for "no proven standard layout". The note's warning that data goes to Anthropic still stands despite his toggle.

## Build from this

1. **Cowork starter workspace.** `about-me/` (`about-me.md`, `writing-rules.md`, `memory.md`, `my-context-map.md`), `outputs/`, `projects/_template/` (`CLAUDE.md`, `memory.md`, `brief.md`). Add a paste-ready global-instructions file kept in the workspace as the source of truth, with a short required-reading list, guardrails and the "how are you meant to work with me?" check. If you work in cloud sessions or Cowork projects, decide whether native memory replaces `memory.md`; local sessions don't use chat memory. See [[Set Up Claude Cowork]], [[Build a Level 1 Second Brain]], [[Keep CLAUDE.md Lean]].
2. **Context-map generator.** Point Claude at a Notion root page, Drive folder or Obsidian vault. It writes `my-context-map.md` listing each database or folder, its purpose, key fields and the questions it answers, and refreshes when the structure changes. See [[Build a Context Map for a Connected Tool]], [[Tiered Lookup Routing]].
3. **Anti-AI writing rules plus a checker pass.** Rules adapted from Wikipedia's Signs of AI writing to your voice, plus a "flag and rewrite" review of any draft. See [[Write Anti-AI Writing Rules]].
4. **Memory maintenance.** Dated entries; separate durable decisions and preferences from a short session log; monthly compaction using the one-year test; a size cap. See [[Agent Memory Patterns]], [[Context vs Connections]].
5. **Drafts-only email assistant.** Gmail and Calendar connected; send and delete tools on Needs approval or Blocked, read tools on Always allow. A "draft and list, never send" rule, with corrections persisted to memory. Pair with a 9:30 weekday triage. See [[Configure Safe Autonomy Permissions]], [[Permissions and Approval Gates]].
6. **Skills from repeated jobs.** Run a task once by hand, then have skill-creator turn it into a skill that opens with AskUserQuestion and saves to `outputs/<project>/`. See [[Build a Skill from a Successful Run]], [[Workflow Audit into Skills]].
7. **Customised role plugin.** Install an Anthropic plugin (support, legal, sales) and customise it with About Me, products, FAQs and escalation rules. Note your changes so you can redo them after updates. See [[Build vs Install Third-Party Skills]].
8. **Scheduled task pack.** Weekly briefer (Notion + Gmail + Calendar → `outputs/weekly-briefings/YYYY-MM-DD.md` or email) and weekday inbox triage (priority buckets, drafts only). Tag which need local files, and so an awake machine. See [[Schedule Recurring Claude Tasks]], [[Routines and Scheduled Tasks]].
9. **Model routing rule.** Sonnet with extended thinking by default; Opus for structural or multi-step jobs. See [[Route Tasks to the Right Claude Model]].
10. **Remote desktop with guardrails.** An awake desktop with Dispatch on, computer use limited by a deny list (finance, banking, password managers), and Chrome in a mode that still checks actions. If laptop and desktop share a workspace, see [[Sync a Workspace to an Always-On Cloud Agent]] and [[Syncthing]].
11. **Portability bridge.** Generate the Cowork settings text, a Claude Code `CLAUDE.md` and an `AGENTS.md` from one file. See [[Port a Claude Code Brain to Other Agents]], [[Tool-Agnostic Context Files]].

## Beyond the source

*Not said in the video; added at ingest and verified at the links (checked 2026-09-15).*

- **Plans and architecture.** Cowork needs Pro, Max, Team or Enterprise; there's no free tier. It extends Claude Code's agentic architecture to knowledge work with no terminal. On desktop it reads and writes only in folders you grant. It has global instructions and built-in folder instructions, which Claude can update mid-session. Cloud sessions share memory with chat. Approval modes are Manual, Auto (Claude safety-reviews actions first) and Skip (no checks). https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork
- **Cowork projects** are workspaces with their own files, instructions and memory. Memory is on by default and scoped per project. Projects made from an existing folder stay on your computer; the page doesn't say whether project memory works for those (this note's reading). https://support.claude.com/en/articles/14116274-organize-your-tasks-with-projects-in-claude-cowork
- **Memory and local sessions.** Chat memory is shared with Cowork only when Cowork runs in the cloud; Cowork sessions running locally on your computer don't use it. Each project keeps its own separate memory. So his instruction-maintained `memory.md` is still the only memory a local, non-project session gets. https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context
- **Cloud vs local sessions.** Cowork now also runs in the cloud: work continues with the laptop closed and scheduled tasks run with no device online. Local sessions need the desktop app open but reach local files, the browser and computer use directly. That narrows his always-on-desktop case to local work. https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile
- **Scheduled tasks** run remotely on their cadence even when the computer sleeps or the app is closed. They work with connectors and account files but can't be tied to a local folder; tasks needing local files or apps run only locally. Cadences are hourly, daily, weekly, weekdays or manual, created via Scheduled › New task, on all paid plans. https://support.claude.com/en/articles/13854387-schedule-recurring-tasks-in-claude-cowork
- **What the privacy toggle actually does.** The model-improvement setting in Settings › Privacy covers consumer plans (Free, Pro, Max, including Claude Code on those accounts), not Claude for Work or the API. Off means new chats and coding sessions aren't used for future training. Safety-flagged conversations can still be used for trust-and-safety work, and thumbs-up/down feedback is handled separately. https://privacy.claude.com/en/articles/12109829-how-do-i-change-my-model-improvement-privacy-settings, https://privacy.claude.com/en/articles/10023580-is-my-data-used-for-model-training
- **Retention.** With training on, de-identified data can stay in training pipelines up to 5 years. With it off, deleted chats leave back-end storage within 30 days. Policy-flagged inputs and outputs are kept up to 2 years, and feedback 5 years. Incognito chats are never used for training. So the toggle changes training use and retention, not whether Anthropic processes your connected email or Notion data. https://privacy.claude.com/en/articles/10023548-how-long-do-you-store-my-data
- **Claude in Chrome modes:** Manually approve (formerly "Ask before acting"); Automatically approve, which reviews each action and is the Cowork side-panel default; Skip all approvals (formerly "Act without asking"), with no checks. Site prompts distinguish allowing one action from always allowing a site. His 44:33 toggle reads like the old act-without-asking behaviour (this note's interpretation). https://support.claude.com/en/articles/12902446-claude-in-chrome-permissions-guide
- **Computer use in Cowork** is off by default. It asks before accessing each app and supports an app blocklist; investment and crypto apps are blocked by default. It prefers connectors, then the browser, then the screen. Pro and Max only, on macOS 15+ and Windows; the machine must be awake with the app open. Anthropic advises against giving it banking, healthcare or government apps. https://support.claude.com/en/articles/14128542-let-claude-use-your-computer-in-cowork
- **Dispatch** is a limited beta on Pro and Max: one conversation across phone and desktop using local files, connectors, plugins and apps. The computer must be awake with the app open. Setup is Dispatch › Get started, with file-access and keep-awake toggles. Anthropic warns that a manipulated instruction or a phishing link could cascade into hard-to-undo actions on the computer. https://support.claude.com/en/articles/13947068-assign-tasks-from-anywhere-in-claude-cowork
- **Connectors** live under Customize › Connectors, with tool permissions of Always allow, Needs approval or Blocked. Custom connectors are remote MCP servers reached from Anthropic's cloud. https://support.claude.com/en/articles/11176164-use-connectors-to-extend-claude-s-capabilities
- **Gmail sends are approval-gated by default.** The Google Workspace connector can send, reply and forward, and by default Claude asks for approval before each. On Team and Enterprise, owners decide whether members can let these run without asking. https://support.claude.com/en/articles/10166901-use-google-workspace-connectors
- **Skills** live under Customize › Skills, and custom ones can be uploaded as a ZIP. Skills need code execution enabled; with code execution and file creation on, Claude uses the built-in file skills automatically when relevant. https://support.claude.com/en/articles/12512180-use-skills-in-claude
- **Plugins** bundle skills, connectors and sub-agents. In Cowork, Customize on an installed plugin opens a task that adapts them to your workflow. All paid plans. https://support.claude.com/en/articles/13837440-use-plugins-in-claude
- **Legal-plugin market reaction** (his 38:33 aside). After Anthropic's legal plugin, Thomson Reuters, RELX and Wolters Kluwer shares fell about 16%, 14% and 13% on 3 February 2026. https://www.morningstar.com/stocks/reuters-relx-wolters-stocks-crushed-after-anthropic-debuts-claude-legal-plug-in
- **Wikipedia: Signs of AI writing** is an advice page from WikiProject AI Cleanup, not policy. It covers content, language, formatting, communication, markup and citation tells, and warns these are signs rather than proof and often appear in human writing. So a rules file built from it is a starting list, not a guarantee. https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing
- **frontend-slides** (zarazhangrui) is an open-source skill producing single-file HTML decks with inline CSS and JS, with PowerPoint conversion and visual style previews. https://github.com/zarazhangrui/frontend-slides
- **One Gmail account:** third-party 2026 guides report the Google connector authorises one account at a time, e.g. https://www.claudetraining.com/claude-multiple-gmail-accounts *(not confirmed in Anthropic docs)*.
