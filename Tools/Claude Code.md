# Claude Code

## What it is

Claude Code is Anthropic's agent harness, and it's where [[Nate Herk]] runs his second brain. In [[Nate Herk - Every Level of a Claude Second Brain]] it's the default runtime: the brain is a folder of markdown that Claude Code opens. CLAUDE.md does the routing, auto memory keeps notes, and skills run his interviews and pull in meeting transcripts. The official product description is under *Beyond the source*.

He stresses that the brain isn't locked to Claude Code. He refers to Claude Code a lot, but the approach works with any AI model ([01:42](https://www.youtube.com/watch?v=DTCyvo6cC54&t=102s)). Because the brain is just files and folders, he also runs it through [[OpenAI Codex]] and [[Hermes Agent]] ([01:46](https://www.youtube.com/watch?v=DTCyvo6cC54&t=106s), [01:48](https://www.youtube.com/watch?v=DTCyvo6cC54&t=108s), [01:50](https://www.youtube.com/watch?v=DTCyvo6cC54&t=110s)).

The other sources use it well beyond coding. [[The Coding Sloth - 1000 Hours of Claude Code Lessons]] notes it runs in the terminal, IDEs and the web ([00:57](https://www.youtube.com/watch?v=YAsxyoTWFDA&t=57s), [01:12](https://www.youtube.com/watch?v=YAsxyoTWFDA&t=72s)). [[Simon Pittman - Set Up Claude Cowork]] shows it as the Code tab beside [[Claude Cowork]] ([03:26](https://www.youtube.com/watch?v=pl90LATQlHI&t=206s)). [[Chase AI - The Agentic OS Setup for Claude Code]] and [[Jay E - The ARMS Framework for a Claude Agentic OS]] make it the engine of an [[Agentic OS]], and Chase says the approach also works in Codex or with a local model ([01:38](https://www.youtube.com/watch?v=HRw-vP0j8OM&t=98s)). Newer sources add the desktop app for non-coders ([[Nate Herk - Claude as a One-Person Marketing Team]]) and the build step after [[Claude Design]]. Below, each feature gets a line or two per source, a link to the deeper note, and current behaviour under *Beyond the source*.

## How sources use it

### CLAUDE.md, /init and @ imports

**[[Nate Herk - Every Level of a Claude Second Brain]]**

- **Where every brain starts.** A CLAUDE.md plus some folders is the starting point; on Codex or a similar tool it would be an AGENTS.md ([04:23](https://www.youtube.com/watch?v=DTCyvo6cC54&t=263s)). It loads at session start and works almost like that project's system prompt ([04:29](https://www.youtube.com/watch?v=DTCyvo6cC54&t=269s), [04:31](https://www.youtube.com/watch?v=DTCyvo6cC54&t=271s)).
- **Treat it as a router.** Besides role and priorities, it holds routing rules, such as which folder holds personal info and which the Q1 priorities ([04:37](https://www.youtube.com/watch?v=DTCyvo6cC54&t=277s), [04:43](https://www.youtube.com/watch?v=DTCyvo6cC54&t=283s)).
- **Why routing matters.** If Claude asks for info you know is in the project, you probably never told it where to look ([04:51](https://www.youtube.com/watch?v=DTCyvo6cC54&t=291s), [05:00](https://www.youtube.com/watch?v=DTCyvo6cC54&t=300s)). Claude Code won't search your whole codebase on its own, and you wouldn't want it to, because that wastes time and tokens ([05:03](https://www.youtube.com/watch?v=DTCyvo6cC54&t=303s), [05:07](https://www.youtube.com/watch?v=DTCyvo6cC54&t=307s)). Set up properly, you stop re-explaining and Claude knows where to look and why ([05:14](https://www.youtube.com/watch?v=DTCyvo6cC54&t=314s), [05:18](https://www.youtube.com/watch?v=DTCyvo6cC54&t=318s)).
- **Failure mode.** A CLAUDE.md that grows too big gets messy and starts to feel ignored ([05:19](https://www.youtube.com/watch?v=DTCyvo6cC54&t=319s), [05:23](https://www.youtube.com/watch?v=DTCyvo6cC54&t=323s)). Depending on routing, lookups also tend toward exact-word matching ([05:25](https://www.youtube.com/watch?v=DTCyvo6cC54&t=325s)).
- **His Level 1 example file** says it loads whenever Claude Code opens in that folder ([05:41](https://www.youtube.com/watch?v=DTCyvo6cC54&t=341s)) and calls itself the single file telling the AI who you are, how you work and where things live ([05:44](https://www.youtube.com/watch?v=DTCyvo6cC54&t=344s)). At Level 1, that file plus a few folders is the whole brain ([05:47](https://www.youtube.com/watch?v=DTCyvo6cC54&t=347s)). Build steps: [[Build a Level 1 Second Brain]].
- **Self-maintained decision log.** CLAUDE.md can tell Claude to append dated decisions whenever something big changes ([06:10](https://www.youtube.com/watch?v=DTCyvo6cC54&t=370s)).
- **No proven standard layout.** Beyond a context folder and CLAUDE.md, nobody has proven a best layout ([06:42](https://www.youtube.com/watch?v=DTCyvo6cC54&t=402s)). Don't copy his or anyone's as "the" way ([06:55](https://www.youtube.com/watch?v=DTCyvo6cC54&t=415s)); what matters is routing that makes sense to you and the AI ([07:03](https://www.youtube.com/watch?v=DTCyvo6cC54&t=423s)).
- **The router grows with the brain.** At Level 2 it still routes to context, projects and decisions, and adds the wiki, references and a memory file ([10:26](https://www.youtube.com/watch?v=DTCyvo6cC54&t=626s), [10:35](https://www.youtube.com/watch?v=DTCyvo6cC54&t=635s)).
- **The lookup order he expects.** For something discussed last week on a quarterly project, check the quarterly-projects file first ([28:17](https://www.youtube.com/watch?v=DTCyvo6cC54&t=1697s)), then the wiki and meeting transcripts ([28:21](https://www.youtube.com/watch?v=DTCyvo6cC54&t=1701s)), and only then pull live data from ClickUp ([28:27](https://www.youtube.com/watch?v=DTCyvo6cC54&t=1707s)). The captions call these projects "OTAs"; the exact term is *(unclear in captions)*. See [[Tiered Lookup Routing]].

### Auto memory, /memory and past sessions

**[[Nate Herk - Every Level of a Claude Second Brain]]**

- **What it does.** Claude Code's auto memory lets the AI write and update the memory file itself, so you don't have to think about it ([10:48](https://www.youtube.com/watch?v=DTCyvo6cC54&t=648s), [10:52](https://www.youtube.com/watch?v=DTCyvo6cC54&t=652s)).
- **How to toggle it.** The /memory command shows whether auto memory is on and lets you switch it on ([10:57](https://www.youtube.com/watch?v=DTCyvo6cC54&t=657s), [10:58](https://www.youtube.com/watch?v=DTCyvo6cC54&t=658s), [11:01](https://www.youtube.com/watch?v=DTCyvo6cC54&t=661s)).
- **It keeps growing.** In his Level 4 example the memory is still there and has grown ([23:19](https://www.youtube.com/watch?v=DTCyvo6cC54&t=1399s)).
- **The portability catch.** CLAUDE.md and the self-updating memory are both Claude Code-specific, which works against a tool-agnostic brain ([11:05](https://www.youtube.com/watch?v=DTCyvo6cC54&t=665s), [11:10](https://www.youtube.com/watch?v=DTCyvo6cC54&t=670s)).
- See [[Claude Code Auto Memory]], and *Beyond the source* for where this memory lives on disk.

- [[The Coding Sloth - 1000 Hours of Claude Code Lessons]]: fuller context means a "dumb zone" of forgetting and contradictions ([13:06](https://www.youtube.com/watch?v=YAsxyoTWFDA&t=786s)); he cites limits of about 300K and 1M ([13:21](https://www.youtube.com/watch?v=YAsxyoTWFDA&t=801s)) and sees quality dip past 100–200K ([13:37](https://www.youtube.com/watch?v=YAsxyoTWFDA&t=817s)). Run /context before big tasks ([13:45](https://www.youtube.com/watch?v=YAsxyoTWFDA&t=825s)), start a new session per task ([14:04](https://www.youtube.com/watch?v=YAsxyoTWFDA&t=844s)), cut research tangents ([14:28](https://www.youtube.com/watch?v=YAsxyoTWFDA&t=868s)) and be very specific ([14:45](https://www.youtube.com/watch?v=YAsxyoTWFDA&t=885s)). After an automatic compact mid-task, start fresh; otherwise run /compact yourself with what to keep ([14:59](https://www.youtube.com/watch?v=YAsxyoTWFDA&t=899s), [15:13](https://www.youtube.com/watch?v=YAsxyoTWFDA&t=913s)).
- [[Ras Mic - How AI Agents and Claude Skills Work]]: about 10% is used before you start; stay between fresh and roughly 70% ([31:19](https://www.youtube.com/watch?v=S_oN3vlzpMw&t=1879s)).

## Beyond the source

*Not from any video. Each item was checked on 2026-09-15 at the linked page.*

**CLAUDE.md and memory**

- **Official description.** Claude Code is an agentic coding tool that reads your codebase, edits files, runs commands and integrates with development tools, in the terminal, IDEs, a desktop app and the browser. <https://code.claude.com/docs/en/overview>
- **How CLAUDE.md loads.** A project file lives at `./CLAUDE.md` or `./.claude/CLAUDE.md`. At launch Claude Code loads CLAUDE.md from the working directory and every directory above it; subdirectory files load only when Claude reads files there. The docs suggest under about 200 lines per file, and `/context` shows which memory files loaded. <https://code.claude.com/docs/en/memory#how-claude-md-files-load>
- **Nuance on "like a system prompt".** CLAUDE.md arrives as a user message *after* the system prompt, so strict compliance isn't guaranteed; use hooks for behaviour that must always happen. It's read at session start (the project-root file is re-read after /compact) and then stays in context, so its tokens go out with every request, softened by prompt caching. That backs Ras Mic's per-turn cost point, and the costs page likewise says to move specialised instructions into on-demand skills. <https://code.claude.com/docs/en/memory#troubleshoot-memory-issues>, <https://code.claude.com/docs/en/costs#why-usage-climbs-in-a-long-session>, <https://code.claude.com/docs/en/costs#move-instructions-from-claude-md-to-skills>
- **Interview-style /init.** `CLAUDE_CODE_NEW_INIT=1` makes /init ask whether to set up CLAUDE.md, skills and hooks, explore with a subagent, ask follow-ups and propose before writing. <https://code.claude.com/docs/en/memory#set-up-a-project-claude-md>
- **How `@` imports behave.** Paths resolve relative to the importing file, imports nest up to four hops, and imported files load at launch, so the `@AGENTS.md` trick removes duplication but doesn't save tokens. <https://code.claude.com/docs/en/memory#import-additional-files>
- **Claude Code reads CLAUDE.md, not AGENTS.md.** For a repo with AGENTS.md, the docs recommend a CLAUDE.md that imports `@AGENTS.md`, or a symlink. <https://code.claude.com/docs/en/memory#agents-md>
- **Auto memory: what the docs say.**
  - **On by default.** The video presents it as something to switch on. The /memory toggle writes `autoMemoryEnabled` to `~/.claude/settings.json`; `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` turns it off.
  - **Stored outside the repo.** Memory lives per project at `~/.claude/projects/<project>/memory/` with a `MEMORY.md` index. The index's first 200 lines or 25KB load every session; topic files are read on demand; it stays on the local machine.
  - **Nuance vs the video.** The memory.md in his example folders isn't where Claude Code keeps auto memory by default. For Codex or another agent to "look in the memory file", route it to the `~/.claude/projects/...` path or move the directory with `autoMemoryDirectory` (an absolute path or one starting `~/`). Pointing it into the vault is my suggestion, not the video's or the docs'.
  - **Learnings vs instructions.** Auto memory holds what Claude learns itself, including a `feedback` type for your corrections. CLAUDE.md is for facts you'd otherwise re-explain, such as a mistake Claude makes twice, with multi-step procedures moved to skills. The 32-tricks habit of logging gotchas into CLAUDE.md fits that, as long as entries stay short.

  <https://code.claude.com/docs/en/memory#auto-memory>
- **Session transcripts.** Chase AI's session mining reads `~/.claude/projects/<project>/<session-id>.jsonl`, deleted after 30 days by default (`cleanupPeriodDays`); the docs call the format internal. <https://code.claude.com/docs/en/sessions#where-transcripts-are-stored>

**Skills, agents and worktrees**

- **Skills basics.** A skill is a folder holding `SKILL.md`, in `~/.claude/skills/<name>/` (personal) or `.claude/skills/<name>/` (project), not a single `techdebt.md` file as the 32-tricks video implies. Only the description sits in context; the body loads when you invoke `/skill-name` or Claude judges it relevant, which is why a Grill Me or transcript-pull skill costs little until used. `disable-model-invocation: true` limits a skill to manual invocation. <https://code.claude.com/docs/en/skills>
- **Subagents.** A subagent file can set `model: haiku`. In interactive sessions subagents run in the background by default, they can spawn their own subagents up to three layers deep, and subagents Claude names when spawning them can message each other, so the 32-tricks claim that subagents can't talk to each other is dated. The `/agents` wizard was removed in v2.1.198; ask Claude to write the file. <https://code.claude.com/docs/en/sub-agents>
- **Agent teams and dynamic workflows.** Teams are experimental, off until `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`, use significantly more tokens, and the docs suggest 3–5 teammates. Dynamic workflows are JavaScript scripts Claude writes and a runtime runs in the background, up to 16 agents at once and 1,000 per run. <https://code.claude.com/docs/en/agent-teams>, <https://code.claude.com/docs/en/workflows>
- **Worktrees.** `--worktree` (or `-w`) creates `.claude/worktrees/<name>/` on branch `worktree-<name>`, and a subagent with `isolation: worktree` gets its own. <https://code.claude.com/docs/en/worktrees>

**Context, models and MCP**

- **Context and effort.** Fable models, Sonnet 5, Opus 4.6+ and Sonnet 4.6 support a 1M-token window, by plan, and `/autocompact` sets when compaction runs. <https://code.claude.com/docs/en/context-window> The ultrathink keyword now adds an in-context instruction for one turn; the effort level sent to the API is unchanged, and Fable, Sonnet 5 and Opus 4.7+ use adaptive reasoning with no fixed 32K budget. Set effort with `/effort`; the `opusplan` alias plans with Opus and executes with Sonnet, matching the Coding Sloth's split. <https://code.claude.com/docs/en/model-config>
- **MCP context cost.** Tool search is on by default, so only tool names enter context until a tool is used, which weakens the endpoint-swap advice; check `/context` first. The costs page still rates CLIs like `gh` leaner than MCP servers. <https://code.claude.com/docs/en/mcp>, <https://code.claude.com/docs/en/costs#reduce-mcp-server-overhead>

**Scheduling and loops**

- **Scheduling options, relevant to the cron points.**

  | Option | Where it runs | Key limits |
  |---|---|---|
  | Routines | Anthropic's cloud, so they keep running with the laptop closed | Research preview; minimum interval one hour; created with `/schedule`; can fire on API calls or GitHub events |
  | Desktop scheduled tasks | Your machine | App open and machine awake; each run is a fresh session. The Desktop Routines page also creates remote routines that run with the computer off |
  | `/loop` | Your current session | Stops when the session exits; unexpired tasks return on `--resume` or `--continue`; recurring tasks expire after 7 days |

  These give you a scheduler, but you still design the sync and refresh jobs an always-on brain needs, as the second-brain video says. The 32-tricks "three days" is now 7, and Jay E's hoped-for hosted runs exist as remote routines, working from a fresh repo clone rather than persistent local files. <https://code.claude.com/docs/en/scheduled-tasks>, <https://code.claude.com/docs/en/routines>, <https://code.claude.com/docs/en/desktop-scheduled-tasks>
- **Cowork scheduled tasks run remotely,** even with the computer asleep or the app closed. They can't be tied to a local folder, and tasks needing local files or apps run only locally, so Simon Pittman's keep-it-on advice now covers only those. <https://support.claude.com/en/articles/13854387-schedule-recurring-tasks-in-claude-cowork>
- **How /goal judges.** It wraps a session-scoped, prompt-based Stop hook: after each turn a small fast model (Haiku by default) returns met, not yet met or impossible. It runs no tools and judges only the transcript, the gap the Unlazy video names; the docs narrow it by asking for one measurable end state plus a stated check, such as `npm test` exiting 0. A goal doesn't change permission mode. <https://code.claude.com/docs/en/goal>
- **Remote Control** needs a Pro, Max, Team or Enterprise login, not an API key; on Team and Enterprise an Owner must switch it on first. Execution and files stay local, but traffic runs through the Anthropic API and the transcript is stored on Anthropic servers while connected. <https://code.claude.com/docs/en/remote-control>

**Hooks, permissions and headless runs**

- **Hooks.** The `Notification` event fires when Claude awaits input or permission; `/hooks` only browses, so add hooks in settings JSON or ask Claude. Hooks run deterministically, so they beat a CLAUDE.md line for checkpointing unattended loops. <https://code.claude.com/docs/en/hooks-guide>
- **Permissions caveats.** Rules are checked deny, then ask, then allow. Read and Edit deny rules don't stop a script that opens files itself, and Bash rules match command text, not the program; the sandbox adds OS-level enforcement. `bypassPermissions` is for containers or VMs, and auto mode (a classifier reviews actions) is the middle path, so allow and deny lists aren't quite "the same speed without the danger". <https://code.claude.com/docs/en/permissions>
- **Headless runs.** `claude -p` starts in Manual permission mode, so dashboard buttons need `--allowedTools` or `--permission-mode`; `/skill-name` works in the prompt; `--bare` skips CLAUDE.md and skills and needs an API key. <https://code.claude.com/docs/en/headless> The separate Agent SDK credit was paused on 2026-06-15, and `claude -p` still draws on plan limits. <https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan>
- **Small commands.** `/btw` answers from context with no tools and stays out of history; a `!` command's output enters the conversation; voice dictation is hold or tap Space once enabled. <https://code.claude.com/docs/en/interactive-mode>
- **Ultraplan is gone.** The Ultraplan research preview, including the `/ultraplan` command and keyword, has been removed; the docs point to plan mode locally or Claude Code on the web for cloud sessions. <https://code.claude.com/docs/en/ultraplan>
- **Data usage, relevant to his privacy point.** Prompts and outputs go over the network to the model provider. On consumer plans (Free, Pro, Max) a setting controls training use, with 5-year retention if allowed and 30 days if not. Under commercial terms (Team, Enterprise, API) data isn't used for training unless the customer opts in, standard retention is 30 days, and zero data retention is available for qualified Enterprise accounts. Claude Code also runs on Amazon Bedrock, Google Cloud's Agent Platform and Microsoft Foundry. <https://code.claude.com/docs/en/data-usage>
