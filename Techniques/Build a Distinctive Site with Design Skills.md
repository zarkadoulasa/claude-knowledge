# Build a Distinctive Site with Design Skills

## Goal

Finish a landing page or small marketing site whose look comes from a deliberate brief, real references and designer-written skills, not the model's house style, with a review log showing it passed.

- **The skill chain** comes from [[AI LABS - Claude Design Skills for Beautiful Sites]]: generate, then refine, then review and rerun.
- **The reference and self-check habits** come from [[Nate Herk - 32 Tricks to Level Up Claude Code]].
- **Why it works:** [[Escaping the Default AI Design Look]].

## Use when

- **Your drafts look like every other AI site.** AI LABS say that happens even after some impressive-looking skill workflows [00:05](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=5s)–[00:11](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=11s).
- **You're building a landing page with one job,** getting visitors to act [05:49](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=349s)–[05:55](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=355s).
- **You have a built design that needs polish, not a rebuild** [02:40](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=160s), [05:01](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=301s).
- **You admire some sites and want their feel without copying them** [10:05](https://www.youtube.com/watch?v=jqoFP9QapXI&t=605s), [10:24](https://www.youtube.com/watch?v=jqoFP9QapXI&t=624s).

## Prerequisites

- **A surface.** Either [[Claude Design]], where AI LABS ran most demos [00:51](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=51s), or [[Claude Code]] in a git repository. AI LABS say the same skills work in both, and in [[OpenAI Codex]] [01:02](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=62s)–[01:07](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=67s). Plans and access are under Beyond the source.
- **Code execution and file creation turned on** if you add skills through the Claude apps (Beyond the source).
- **git**, if you want the regression-aware review. AI LABS say it works better connected to GitHub [09:24](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=564s).
- **Python 3 with Pillow**, only if you use tastemaker's extraction scripts (Beyond the source).
- **Screenshots of sites you admire**, plus optionally their HTML and styling [10:05](https://www.youtube.com/watch?v=jqoFP9QapXI&t=605s)–[10:22](https://www.youtube.com/watch?v=jqoFP9QapXI&t=622s).
- **Time to read each third-party skill before installing it.** [[Ras Mic]] calls skill marketplaces an easy way to attack someone ([[Ras Mic - How AI Agents and Claude Skills Work]] [13:02](https://www.youtube.com/watch?v=S_oN3vlzpMw&t=782s)–[13:07](https://www.youtube.com/watch?v=S_oN3vlzpMw&t=787s)).

## Steps

1. **Choose the surface.**
   - **Claude Design:** skills you add in Claude settings are available there with no separate install [00:51](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=51s)–[01:00](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=60s). In the vault's view, it's the quicker place to iterate on looks.
   - **Claude Code:** in the vault's view, the better fit for the git-based review skill and for skills that run local scripts or tools. You can start in Claude Design and hand off; see Beyond the source.

3. **Install the kit.**
   - **Claude apps route.** Under Customize > Skills, the + button offers create with Claude, write skill instructions, or upload a skill ([[Simon Pittman - Set Up Claude Cowork]] [32:36](https://www.youtube.com/watch?v=pl90LATQlHI&t=1956s)–[32:44](https://www.youtube.com/watch?v=pl90LATQlHI&t=1964s)). Upload each skill folder as a ZIP (format and required settings under Beyond the source). In Claude Design, type a slash plus the skill name [02:14](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=134s).
   - **Claude Code route.** Install from each repo. The commands below come from the repo READMEs and were checked on 2026-09-15:

   npx skills@latest add emilkowalski/skills

   # ConardLi garden-skills: web-design-engineer only
   npx skills add ConardLi/garden-skills -s web-design-engineer

   #   /plugin marketplace add ConardLi/garden-skills
   #   /plugin install web-design-skills@garden-skills

   # elayadesign landing-page-design (per its README: clone, then copy the skill folder in)
   mkdir -p .claude/skills
   git clone https://github.com/elayadesign/ai-design-skills.git /tmp/ai-design-skills
   cp -r /tmp/ai-design-skills/skills/landing-page-design .claude/skills/

   # Jakub Krehel: better-layout, interface-review, better-typography, ...
   npx skills add jakubkrehel/skills
   #   or: /plugin marketplace add jakubkrehel/skills
   #       /plugin install interfaces@interfaces

   # tastemaker (inside Claude Code)
   #   /plugin marketplace add codeswithroh/tastemaker
   #   /plugin install tastemaker@codeswithroh

   # designer-skills: screen critique + Gestalt law skills (inside Claude Code)
   #   /plugin marketplace add Owl-Listener/designer-skills
   #   /plugin install visual-critique@designer-skills

   # Anthropic frontend-design (official marketplace; docs syntax)
   #   /plugin install frontend-design@claude-plugins-official

   # GSAP official skills
   npx skills add https://github.com/greensock/gsap-skills

   # UI UX Pro Max (inside Claude Code)
   #   /plugin marketplace add nextlevelbuilder/ui-ux-pro-max-skill
   #   /plugin install ui-ux-pro-max@ui-ux-pro-max-skill

   # One taste preset only (Leon Lin's taste-skill shown)
   npx skills add https://github.com/Leonxlnx/taste-skill --skill "minimalist-ui"

   Meng To's repo has no installer. For Claude Code, its README suggests referencing the relevant SKILL.md from CLAUDE.md, copying the skill into your skills folder, or opening the SKILL.md as working context. build-awwwards-quality-sites lives at `agent-skills/web-design/build-awwwards-quality-sites/`.

4. **Write the brief and settle the page type.**
   - **Landing page or homepage?** A homepage serves many audiences; a landing page exists to get people to act [05:49](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=349s)–[05:55](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=355s). For a landing page, name the single action.
   - **Describe motion by name, not by vibe.** animation-vocabulary exists to turn vague motion descriptions into exact terms [01:35](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=95s)–[01:41](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=101s).
   - **Fill in `design/brief.md`** (starter below).

5. **Gather references.**
   - Save screenshots of sites you admire in `design/references/` [10:05](https://www.youtube.com/watch?v=jqoFP9QapXI&t=605s)–[10:10](https://www.youtube.com/watch?v=jqoFP9QapXI&t=610s).
   - Optionally save their HTML and styling too; Nate treats what comes back as a template to make your own [10:15](https://www.youtube.com/watch?v=jqoFP9QapXI&t=615s)–[10:28](https://www.youtube.com/watch?v=jqoFP9QapXI&t=628s).
   - With tastemaker, give it the site brief together with your style requirements [11:08](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=668s)–[11:13](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=673s).

6. **Generate.**
   - Run the generator: a slash, the skill name, and a description of the site [02:14](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=134s)–[02:16](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=136s).
   - Answer its intake questions in full; it builds once you do [02:23](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=143s)–[02:31](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=151s).
   - If a generator doesn't interview you, tell Claude to keep asking with its AskUserQuestion tool until it's 95% confident [03:42](https://www.youtube.com/watch?v=jqoFP9QapXI&t=222s)–[03:49](https://www.youtube.com/watch?v=jqoFP9QapXI&t=229s).
   - Expect a decent but imperfect first pass. AI LABS's first emil-design-eng build was minimal and monotone, with animations that were unpolished and partly out of sync [02:31](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=151s)–[02:38](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=158s).
   - **Or settle the direction before any code** (AI LABS's June video). frontend-design makes the model commit to a design direction before writing anything [01:20](https://www.youtube.com/watch?v=Ot582-E61ac&t=80s); AI LABS say the original needed updating for newer models [02:32](https://www.youtube.com/watch?v=Ot582-E61ac&t=152s). UI UX Pro Max instead searches its own database and hands the model an industry-fitted design system [06:27](https://www.youtube.com/watch?v=Ot582-E61ac&t=387s). For product screens see [[Build Product UI from a Component Registry]]; to reuse a system, [[Create and Reuse a Claude Design System]].

7. **Refine motion.**
   - Run `/animate` on the built site. It works out what should move and what shouldn't [02:44](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=164s)–[02:50](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=170s), and in their demo motion ended up synced with the scroll [02:50](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=170s)–[02:57](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=177s).
   - On apps, point it at functional details such as form submission and hover graphics [03:22](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=202s)–[03:36](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=216s).
   - **On landing pages, swap the stock reveal for GSAP.** AI LABS's June video says models almost always add the same slide-in on scroll [08:13](https://www.youtube.com/watch?v=Ot582-E61ac&t=493s); GSAP's official skills steer away from animating size or position, which makes the browser rebuild the page every frame [08:50](https://www.youtube.com/watch?v=Ot582-E61ac&t=530s). Full playbook: [[Build a Scroll-Driven Landing Page]].

8. **Refine layout.**
   - Run `/better-layout` and tell it to fix all its flags [10:05](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=605s).
   - Expect precise corrections, such as how many extra pixels a cramped date needs [09:59](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=599s)–[10:03](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=603s), not a new look [10:07](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=607s)–[10:13](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=613s).

9. **Self-check with screenshots and a browser.**
   - Have Claude screenshot the page and judge whether the layout looks right [09:06](https://www.youtube.com/watch?v=jqoFP9QapXI&t=546s)–[09:15](https://www.youtube.com/watch?v=jqoFP9QapXI&t=555s). Then fix and repeat, as Nate does for about three passes before looking himself [09:15](https://www.youtube.com/watch?v=jqoFP9QapXI&t=555s)–[09:27](https://www.youtube.com/watch?v=jqoFP9QapXI&t=567s).
   - Check buttons and forms in a browser [09:33](https://www.youtube.com/watch?v=jqoFP9QapXI&t=573s)–[09:46](https://www.youtube.com/watch?v=jqoFP9QapXI&t=586s). web-design-engineer focuses on visuals rather than function [04:09](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=249s)–[04:12](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=252s), so this check is separate. Nate calls this hack "Chrome DevTools" but shows no setup; he most likely means the Chrome DevTools MCP server *(unclear in captions)*. [[Claude in Chrome]] can do the same job.

10. **Review and score.** Use one of these:
    - **web-design-engineer, run on the existing design:** scores it area by area [05:01](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=301s)–[05:07](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=307s).
    - **interface-review, on a branch or PR:** compares before and after, flags regressions with the change that caused them, and checks animations, accessibility and screen sizes [09:24](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=564s)–[09:47](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=587s).
    - **Screen critique:** lists what stands out first plus type and spacing problems [12:03](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=723s)–[12:12](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=732s). Then apply the perception laws [12:12](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=732s)–[12:16](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=736s).

    Log each round in `design/review-log.md`.

11. **Iterate until it passes.**
    - AI LABS say to fix and rerun until the design reaches a perfect score and matches what you want [05:07](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=307s)–[05:14](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=314s).
    - The vault swaps "perfect" for a set threshold: use the pass bar in the starter log below, with a cap of three rounds (see Pitfalls).
    - If a round comes back merely okay, push back: scrap it and ask for a more elegant version or a different approach [08:02](https://www.youtube.com/watch?v=jqoFP9QapXI&t=482s)–[08:09](https://www.youtube.com/watch?v=jqoFP9QapXI&t=489s).
    - **Or send targeted fixes instead of a redo.** In [[Nate Herk - The Scrollcraft Website Design Skill]], Nate opens with what worked [12:19](https://www.youtube.com/watch?v=QUI6Ug4cHnE&t=739s), gives one fix per section from the hero down [12:38](https://www.youtube.com/watch?v=QUI6Ug4cHnE&t=758s) and cuts what doesn't work [13:52](https://www.youtube.com/watch?v=QUI6Ug4cHnE&t=832s). Template: [[Build a Scroll-Driven Landing Page]].

12. **Keep the lesson.**
    - Have Claude write what fixed things into the relevant skill or CLAUDE.md [08:15](https://www.youtube.com/watch?v=jqoFP9QapXI&t=495s)–[08:22](https://www.youtube.com/watch?v=jqoFP9QapXI&t=502s).
    - If the whole run went well, consider turning it into your own skill. Ras Mic argues an agent needs the context of a successful run of your own ([12:50](https://www.youtube.com/watch?v=S_oN3vlzpMw&t=770s)–[12:55](https://www.youtube.com/watch?v=S_oN3vlzpMw&t=775s)).
    - See [[Build a Skill from a Successful Run]] and [[Skill Improvement Loop]].

## Starter files & prompts

*Vault starter content: original wording, not taken from any source.*

**Folder layout**

```text
my-site/
├── CLAUDE.md                  # Claude Code only: short "UI work" section (below)
├── .claude/skills/            # project-scoped kit: 1 generator, ≤2 refiners, 1 reviewer
└── design/
    ├── brief.md
    ├── references/            # screenshots, plus saved HTML/CSS for study only
    ├── screenshots/           # round-N-375.png, round-N-1440.png
    └── review-log.md
```

**`design/brief.md`**

```markdown
# Site brief
- Page type: landing page | homepage | multi-page site
- The one action (landing pages only): e.g. "book a 20-minute demo"
- Audience and arrival: who lands here, from where (ad, search, newsletter)
- Offer and proof: what they get; real testimonials/numbers we may use
- Feel in five words: e.g. calm, precise, warm, editorial, quick
- Avoid: e.g. indigo gradients, glass on everything, stock bento grids
- References: design/references/*.png, and what to take from each (type? rhythm? motion?)
- Motion, named: e.g. staggered hero reveal; hover lift on cards; no parallax
- Must hold up at: 375px and 1440px
- Pass bar: see design/review-log.md
```

**Generate prompt** (swap in your chosen generator)

```text
/web-design-engineer
Build the page described in design/brief.md. First ask me whatever the brief
leaves open, in a single round. Ground the look in design/references/: borrow
structure, rhythm and type treatment, never logos, copy, images or code.
Show me the colours, type scale, spacing and motion plan before the full build.
```

**Review-round prompt**

```text
Review round {N} for design/brief.md.
1. Screenshot the page at 375px and 1440px into design/screenshots/.
2. Run /better-layout and fix every flag, or note why a flag is waived.
3. Critique the current design (web-design-engineer critique, or
   /visual-critique:critique-screen). Record the scores or P1/P2/P3 list,
   the top three fixes and the screenshot paths in design/review-log.md.
4. Apply the fixes, re-screenshot, then click every button, link and form
   in the browser and note anything broken.
5. Stop and report if the pass bar is met or this was round 3.
```

**`design/review-log.md`**

```markdown
# Review log
Pass bar: every critique dimension ≥ 8/10 · no critical fixes open · no P1 items ·
interface-review verdict "Approve" (if used) · stop after round 3 regardless

| Round | Reviewer | Score / verdict | Top three fixes | Screenshots | Pass? |
|---|---|---|---|---|---|
| 1 (example row) | web-design-engineer | 6.5 overall | CTA contrast; hero hierarchy; card spacing | screenshots/round-1-*.png | no |
```

**`CLAUDE.md` section** (Claude Code)

```markdown
## UI work
- Brief: design/brief.md · References: design/references/
- Order: generator → /animate (apps) → /better-layout → critique → fix → re-review
- References guide structure and feel only; never ship their assets, copy or code
- Log each review round in design/review-log.md; stop at the pass bar or round 3
```

## Done when

- [ ] `brief.md` names the page type and, for a landing page, the single action
- [ ] At least two references are saved, and the brief says what each one contributes
- [ ] Only one generator skill ran for this build
- [ ] At most one taste preset is active
- [ ] Landing-page animation moves transform and opacity, not size or position
- [ ] Every better-layout flag is fixed or waived in the log with a reason
- [ ] The final round has screenshots at phone and desktop widths
- [ ] Every button, link and form has been checked in a browser
- [ ] The review log shows the pass bar met, or round 3 reached with the open issues listed
- [ ] No logos, copy, images or code were lifted from reference sites
- [ ] What you learned is written into CLAUDE.md or a skill

## Pitfalls

- **Skill conflicts.** Overlapping collections each bring their own taste. The Coding Sloth, discussing coding skills, notes that some are subjective and recommends sticking to one group ([08:18](https://www.youtube.com/watch?v=YAsxyoTWFDA&t=498s)–[08:24](https://www.youtube.com/watch?v=YAsxyoTWFDA&t=504s)). Run one generator per build. If two installed skills both claim motion or layout, remove one.
- **Trusting an elaborate skill workflow.** Some skills run impressive workflows and still produce a lookalike site; only a few deliver [00:05](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=5s)–[00:13](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=13s). Judge a skill by its output, not its process.
- **Leaving the brief vague.** *Vault reading, not the video's claim* (it blames each model's default pattern [00:21](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=21s)): specific inputs give a skill more to steer with. Name the single action [06:03](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=363s) and the motion [01:35](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=95s), and answer intake questions fully [02:23](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=143s).
- **Expecting refiners to transform the look.** animate adds little to a landing page unless the motion is scroll-based [02:59](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=179s)–[03:14](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=194s). better-layout makes the design correct, not dramatic [10:07](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=607s)–[10:13](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=613s).
- **Chasing a perfect score.** AI LABS suggest rerunning until the score is perfect [05:07](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=307s)–[05:14](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=314s). The rubric is five dimensions out of 10 (Beyond the source), so set a threshold and a round cap.
- **Running a git-based review without git.** The review skill compares before and after your changes [09:24](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=564s)–[09:30](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=570s). Without a repository it has nothing to compare, so hand off to Claude Code first.
- **Trusting third-party code blindly.** video-to-superprompt runs tools on your machine [07:52](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=472s)–[08:01](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=481s), and tastemaker runs scripts [10:34](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=634s). Read before you install ([13:02](https://www.youtube.com/watch?v=S_oN3vlzpMw&t=782s)).
- **Cloning too literally.** Nate treats a cloned site as a template to make his own [10:24](https://www.youtube.com/watch?v=jqoFP9QapXI&t=624s)–[10:28](https://www.youtube.com/watch?v=jqoFP9QapXI&t=628s). Where to draw the line: Beyond the source.
- **Judging by eye alone.** AI LABS's verdicts are subjective [04:51](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=291s), [11:15](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=675s). Keep screenshots and scores so runs can be compared.
- **Assuming identical results everywhere.** The claim that skills give the same result in any agent is asserted, not shown [01:02](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=62s)–[01:07](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=67s). Script-backed skills can lose features in some tools (Beyond the source).
- **Checking looks but not behaviour.** A visual skill won't catch a broken form [04:09](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=249s). Keep the browser check [09:33](https://www.youtube.com/watch?v=jqoFP9QapXI&t=573s).
- **Pulling in skills you haven't read.** A registry loads other authors' instructions in the middle of a build ([[AI LABS - Eight GitHub Repos to Upgrade Claude Code]] [05:41](https://www.youtube.com/watch?v=Ua0APTMVcb8&t=341s)), which bypasses the read-before-install check. *Vault:* ask the agent which skills it loaded, and read them.

## Variations

- **Nate's clone-an-inspiration-site route (no design skills), in Claude Code:**
  1. Screenshot sites you really like and give them to Claude [10:05](https://www.youtube.com/watch?v=jqoFP9QapXI&t=605s)–[10:10](https://www.youtube.com/watch?v=jqoFP9QapXI&t=610s).
  2. Ask it to make your site look like them. It picks up their design patterns without the generic AI look [10:10](https://www.youtube.com/watch?v=jqoFP9QapXI&t=610s)–[10:15](https://www.youtube.com/watch?v=jqoFP9QapXI&t=615s).
  3. Optionally add the reference site's HTML and styling [10:15](https://www.youtube.com/watch?v=jqoFP9QapXI&t=615s)–[10:22](https://www.youtube.com/watch?v=jqoFP9QapXI&t=622s).
  4. Treat the result as a template and change it until it's yours [10:22](https://www.youtube.com/watch?v=jqoFP9QapXI&t=622s)–[10:28](https://www.youtube.com/watch?v=jqoFP9QapXI&t=628s).
  5. Have Claude run design, screenshot and fix for about three passes before you look [09:15](https://www.youtube.com/watch?v=jqoFP9QapXI&t=555s)–[09:27](https://www.youtube.com/watch?v=jqoFP9QapXI&t=567s).
  6. Tell it not to move to the next to-do until it's 95% confident the current one is good [04:31](https://www.youtube.com/watch?v=jqoFP9QapXI&t=271s)–[04:35](https://www.youtube.com/watch?v=jqoFP9QapXI&t=275s).
- **Landing page:** landing-page-design, then better-layout, then a critique. Confirm the page is built around one action and can be found in search [06:03](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=363s), [06:15](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=375s).
- **Story-led site:** build-awwwards-quality-sites for scroll storytelling [08:47](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=527s)–[08:53](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=533s). To start from a site you've recorded, run video-to-superprompt, which uses tools on your machine to turn the recording into a prompt for your agent [07:52](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=472s)–[08:01](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=481s).
- **Pixel-locked brand:** tastemaker with brand screenshots, so the extracted details carry across every page [10:34](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=634s)–[10:59](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=659s).
- **Skill bake-off** *(vault)*: run the same brief through two or three generators in separate worktrees. Screenshot each, score all of them with the same critique, and keep the winner. See [[Parallel Sessions with Git Worktrees]] and [[Multi-Agent Review and Scoring Loops]].
- **PR gate** *(vault)*: run interface-review on every branch that touches UI before merging, and keep its verdict as evidence. See [[Evidence-Gated Completion Ledger]].

## Where sources disagree

- **How many skills to install.** [[AI LABS - Claude Design Skills for Beautiful Sites]] say add as many of Emil's skills as you like [03:42](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=222s). Their June video says pick one preset [10:15](https://www.youtube.com/watch?v=Ot582-E61ac&t=615s), and their September video says you needn't pick and install each skill yourself, because a registry fetches the relevant ones [05:46](https://www.youtube.com/watch?v=Ua0APTMVcb8&t=346s).
- **Scroll motion.** The August video credits /animate with syncing motion to the scroll [02:50](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=170s). The June video calls the stock scroll reveal the AI tell and uses GSAP for scroll storytelling instead [08:13](https://www.youtube.com/watch?v=Ot582-E61ac&t=493s), [09:08](https://www.youtube.com/watch?v=Ot582-E61ac&t=548s). *Vault reading:* a generic reveal and scroll-linked storytelling are different things.
- **What counts as done.** This note's pass bar adapts AI LABS's advice to rerun until the score is perfect [05:07](https://www.youtube.com/watch?v=Ysr7oNDajJI&t=307s). Nate judges Scrollcraft output by eye, with one feedback round and small follow-ups [12:19](https://www.youtube.com/watch?v=QUI6Ug4cHnE&t=739s).
- **Redo or fix.** [[Nate Herk - 32 Tricks to Level Up Claude Code]] says to scrap merely okay work [08:02](https://www.youtube.com/watch?v=jqoFP9QapXI&t=482s). His Scrollcraft video keeps what worked and targets fixes [12:19](https://www.youtube.com/watch?v=QUI6Ug4cHnE&t=739s).

## Beyond the source

*Not from any video. Checked on 2026-09-15 at the links given.*

- **Claude Design access and handoff.**
  - In beta on Pro, Max, Team and Enterprise (Enterprise must opt in), at claude.ai/design or in Claude Desktop.
  - Designs can be handed off to Claude Code, where `/design-sync` pulls in a design system and `/design` works on designs.
  - https://support.claude.com/en/articles/14604416-get-started-with-claude-design · https://claude.com/product/design
- **Skills in the Claude apps.**
  - Path: Customize > Skills > + > Create skill > Upload a skill, with the folder uploaded as a ZIP.
  - Code execution and file creation must be on: Settings > Capabilities, or organisation settings on Team and Enterprise.
  - The help pages don't say uploaded skills appear in Claude Design; that rests on AI LABS.
  - https://support.claude.com/en/articles/12512180-use-skills-in-claude
- **Skills in Claude Code.**
  - Personal skills live at `~/.claude/skills/<name>/SKILL.md`, project skills at `.claude/skills/<name>/SKILL.md`, and plugin skills are invoked as `/plugin-name:skill-name`.
  - `disable-model-invocation: true` means only you can trigger the skill.
  - https://code.claude.com/docs/en/skills
- **`npx skills add owner/repo`** is the skills.sh installer, and it supports Claude Code, Cursor and many other agents. https://skills.sh
- **Repo facts behind the steps.**
  - **Emil Kowalski:** 12 skills today. https://github.com/emilkowalski/skills
  - **web-design-engineer:**
    - Declares a design system before coding and shows an early v0.
    - Its critique scores philosophy alignment, visual hierarchy, craft quality, functionality and originality out of 10, then returns Keep, Fix and three Quick Wins.
    - https://github.com/ConardLi/garden-skills/blob/main/skills/web-design-engineer/references/critique-guide.md
  - **landing-page-design:** a single skill. Its README lists intake questions, page structure, conversion copy and a visual system for type, spacing, radius and motion. For Claude Code you copy the skill folder into `.claude/skills/`. Without a terminal, on Claude.ai, it suggests uploading the SKILL.md to a Project or attaching it to a chat. Fonts, colours, spacing and motion values sit in one editable section near the end of the file. https://github.com/elayadesign/ai-design-skills
  - **build-awwwards-quality-sites:**
    - Writes an art direction before any code and uses GSAP with one smooth-scroll engine.
    - With reduced motion on, it shows final states straight away.
    - It forbids reproducing a reference's assets, code, identity or copy, and requires original or licensed media.
    - https://github.com/MengTo/Skills/blob/main/agent-skills/web-design/build-awwwards-quality-sites/SKILL.md
  - **interface-review:** invoked by the user on a PR, branch, range or uncommitted changes. It tags findings Introduced, Regression or Pre-existing, and ends with Block or Approve, not a numeric score. https://github.com/jakubkrehel/skills/blob/main/skills/interface-review/SKILL.md
  - **better-layout:** covers grouping, alignment and reading order, with severity-rated findings. https://github.com/jakubkrehel/skills/blob/main/skills/better-layout/SKILL.md
  - **tastemaker:**
    - Needs Python 3 and Pillow, falling back to vision if Pillow is missing.
    - Writes `.tastemaker/style-lock.md` and `~/.tastemaker/profile.md`.
    - Its README lists native support for Claude Code (recommended), Windsurf and Gemini CLI. It calls Cursor support degraded, because converting to Cursor's rule format drops the scripts and references.
    - https://github.com/codeswithroh/tastemaker
  - **designer-skills:**
    - Nine plugins ship from this repo, and its marketplace also pulls in four sister collections (33 plugins in all).
    - `/visual-critique:critique-screen` runs seven visual critiques and returns a prioritised fix list.
    - The "perception laws" are most likely the ui-design plugin's law-of-* Gestalt skills; the README says ui-design covers Gestalt and perceptual principles.
    - https://github.com/Owl-Listener/designer-skills · https://github.com/Owl-Listener/designer-skills/tree/main/ui-design/skills
- **Tools added from the June and September AI LABS videos.**
  - **frontend-design:** now plans 4–6 named hex colours, typefaces and ASCII wireframes, checks them against the brief, then builds; it names five AI-look clusters to avoid. It ships in the official marketplace (`/plugin install <name>@claude-plugins-official`). https://github.com/anthropics/claude-code/blob/main/plugins/frontend-design/skills/frontend-design/SKILL.md · https://github.com/anthropics/claude-plugins-official/tree/main/plugins/frontend-design · https://code.claude.com/docs/en/discover-plugins
  - **UI UX Pro Max:** needs Python 3; `--persist` saves `design-system/<project>/MASTER.md`; a paid Premium tier exists. https://github.com/nextlevelbuilder/ui-ux-pro-max-skill
  - **GSAP skills:** prefer transforms and opacity over layout properties. https://github.com/greensock/gsap-skills
  - **taste-skill:** `--skill` installs a single preset. https://github.com/Leonxlnx/taste-skill
  - **UI Skills:** MIT; MCP endpoint `https://www.ui-skills.com/mcp` with tools `list_skills` and `get_skill`, added with `claude mcp add --transport http <name> <url>`. https://github.com/ibelick/ui-skills · https://code.claude.com/docs/en/mcp
